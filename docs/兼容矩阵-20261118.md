## 状态与已读规则

1. 来源和会话组成唯一标识，避免不同软件使用相同 session ID 时串任务。Codex 保留历史 ID 以兼容原有移除记录。
2. 显式开始、工具执行、权限请求、结构化问题、结束和退出事件分别处理；子 Agent 结束不直接完成父任务。有明确轮次 ID 时，迟到的旧轮次结束不会结束新任务。
3. Antigravity 仍有后台工作时不能完成；正常 CLI 退出保留已经收到的未读完成结果。错误、取消和异常退出不触发成功庆祝。
4. 没有原生已读回执的来源，首次采集只建立基线，不恢复全部历史完成记录。接入之后观察到的完成结果持久保留，由用户标记已读。
5. 所有来源统一：待输入、已完成任务成功跳转到聊天或应用后，在本任务中心标为已读并淡出移除。应用跳转等待系统确认成功；打开失败或仅复制恢复命令时保留提醒。运行中任务继续展示。此操作不写入其他客户端的原生已读状态。
6. 单个来源读取失败在兼容窗口显示原因，其他来源继续工作。事件运行 / 等待状态超过 24 小时且没有新事件时不继续显示为活跃，不据此推断完成。

## Claude 与千问的本地接入

Claude Code 额外观察 PostToolUseFailure、PermissionDenied、StopFailure、Elicitation 与 ElicitationResult。API 错误和明确工具中断不播放成功提醒；普通工具失败允许主任务继续。按 tool_use_id 跟踪结构化问题，权限事件因不含 tool_use_id 而使用工具名和输入匹配后续结果。子 Agent 的 agent_id 事件被隔离；并发问题分别解决，其他工具完成不解除等待。新增用户输入开始独立提醒轮次。升级和卸载只移除本工具的命令，即使用户命令与观察命令在同一 Hook 组中也予以保留。

千问「工作」根据本地任务索引与轮次的开始、结束记录跟踪进度，并按工具调用 ID 匹配结构化提问和回答。应用关闭后，未结束的旧轮次退出活跃列表。快照只保存标题、标识和状态等任务元数据。需要在本机有任务记录，纯云端任务暂不覆盖。

## 配置与回退

接入安装器仅为已经存在的客户端目录 / 应用添加配置；显式 `--provider` 可准备指定来源。不改写模型、鉴权、权限策略和已有用户 Hook。无效 JSON 或同名自定义插件冲突时保留原文件并显示错误。每次实际修改前在 `~/.codex/task-manager/backups/hooks-时间戳/` 备份原文件。事件接收器不返回批准 / 拒绝决定，接收失败保持退出码 0 和空输出。

卸载观察配置：

```sh
/usr/bin/python3 ~/.codex/bin/integrations.py --remove
```

只卸载某个来源：

```sh
/usr/bin/python3 ~/.codex/bin/integrations.py --provider claude --remove
```
